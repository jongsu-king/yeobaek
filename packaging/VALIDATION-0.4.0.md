# 0.4.0 검증 기록

2026-11-18 KST에 검증했습니다. 합성 노트와 첨부 파일을 사용했습니다.

## 소스와 배포 파일

- 애플리케이션 Python 모듈은 `f1a7f30`에서 고정했습니다. 이후 변경은 테스트·패키징·검증 문서입니다. Windows·Linux·모바일은 검증된 0.3.1 네이티브 런타임을 재사용했고 macOS는 다시 패키징했습니다.
- 설치 파일 6종의 SHA-256, 포함된 Python 모듈, 버전 정보를 별도로 대조했습니다. 새 `exports` 모듈도 모든 플랫폼에 들어 있습니다.
- Android APK는 기존 테스트 인증서의 v2/v3 서명과 16 KiB 정렬, 버전 0.4.0·코드 3을 확인했습니다. 네이티브 라이브러리 65개는 0.3.1과 동일합니다.
- macOS와 iOS 시뮬레이터 번들은 ARM64 임시 서명의 `codesign --verify --deep --strict` 검사가 통과했습니다. Windows는 코드 서명이 없고 macOS는 공증하지 않았습니다.

## 자동 검사

[Python 3.12의 72개 검사 × Windows·macOS·Linux](https://github.com/jongsu-king/yeobaek/actions/runs/44254176076)가 통과했습니다. 저장 실패·기존 백업 보존, ZIP 첨부 누락과 중복 이름, 코드 예제 링크 보존, UTF-16 검색 범위와 노트 전환, Drive 연결 해제 경쟁 상태, 손상된 첨부 복구와 두 기기의 오프라인 병합을 포함합니다.

Windows와 Linux는 설치된 Python 코드로 PDFium의 PNG 생성, Excel 셀과 수식 읽기를 확인했습니다. 설치 전후의 ZIP 내보내기 두 번에서 `note.md`의 상대 링크, 바이너리 첨부 원본, 기존 파일의 원자적 교체와 다시 읽기도 통과했습니다.

Android는 노트 2개·노트북 1개·수정 기록 4개·한국어 태그·고정 상태·노트북 소속·첨부 원본 바이트를 업데이트 전후와 재실행 뒤에 대조했습니다. 앱 충돌·Python 예외가 수집된 로그에 없었습니다. 화면 조작과 Google 로그인 검사는 수행하지 않았습니다.

첫 Linux 검사는 CI 미러에서 선택한 61 MB CJK 글꼴 다운로드에 약 13분이 걸려 전체 15분 제한으로 끝났습니다. ASCII 입력과 데이터 검증에 필요 없는 글꼴만 제외한 위의 재실행은 전체 통과했습니다. 프로그램과 설치 파일은 바꾸지 않았습니다.

이 Mac의 소스와 모의 Page를 사용한 별도 용량 점검에서는 한글 본문 약 1 KiB짜리 노트 1,000개와 추가 수정 100개, 정확한 1,100개 기록, 복합 검색 결과 20개와 1 MiB 첨부 ZIP의 원본 일치를 확인했습니다. 네이티브 GUI 렌더링이나 다른 운영체제의 성능을 측정한 결과는 아닙니다.

## 검증 범위

- 0.4.0의 Mac 새 버튼 직접 클릭은 화면 제어 도구의 이미지 생성 오류로 완료하지 못했습니다.
- 0.4.0 Linux ARM64와 iOS 시뮬레이터는 포함 코드·패키지·서명을 검사했습니다. 실제 화면 검증 기록은 0.3.0 Ubuntu ARM64의 노트 저장, iOS 26.4 시뮬레이터의 PDF 페이지 이동입니다.
- 실물 Android·iPhone은 연결되지 않았습니다. 실물 모바일 기기 간 Drive 동기화는 미검증이며 iOS ZIP은 시뮬레이터 전용입니다. 실물 iPhone 설치에는 Apple 서명과 프로비저닝이 필요합니다.
- 실제 Drive 검증은 0.3.0에서 Mac의 분리된 두 저장소 및 Mac↔Ubuntu ARM64 간 PDF·Excel 원본 왕복, 오프라인 충돌과 병합·복원으로 수행했습니다. 0.4.0은 같은 프로토콜을 유지하며 오류 복구는 모의 HTTP 경계 검사로 검증했습니다. 모바일 OAuth는 개발용 테스트 사용자 제한을 유지합니다.
